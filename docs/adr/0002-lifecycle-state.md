# ADR-0002: Өмірлік цикл — enum негізіндегі State үлгісі

Мәртебесі: қабылданды
Күні: 2026-11-18 · Қатысушылар: Амангелді Мадияр

## Контекст

R3: INSTALLED → RESOLVED → ACTIVE → STOPPED; заңсыз ауысуға тыйым салынады. Ауысу ережелері бір жерде болуы және тестпен толық тексерілуі керек. Заңсыз әрекет плагин кодын шақырмас **бұрын** тоқтатылуы керек.

## Нұсқалар

1. **`switch`/`if` менеджердің ішінде.**
   + Аз код.
   − Ережелер `start/stop/resolve` әдістеріне шашырайды; жаңа күй қосқанда барлық `switch`-ті өзгерту керек.
2. **Классикалық State: интерфейс + әр күйге бөлек класс.**
   + Кітаптағы форма.
   − Төрт күй үшін 5 файл; күйлерде өріс жоқ, сондықтан бөлек класстар артық.
3. **enum State: әр enum тұрақтысы тек өзіне заңды әрекетті override етеді, қалғаны базалық әдісте исключение лақтырады (таңдалды).**
   + Ережелер бір файлда; кесте түрінде оқылады.
   + Күйлер — синглтондар, тегін салыстыру (`==`).
   + Әр күйдің әрекеті таза функция (жаңа күйді қайтарады) → тесттеу оңай: 4 заңды + 8 заңсыз ауысу параметрленген тестпен.

## Шешім

3-нұсқа. `PluginLifecycle` — State контексі: ағымдағы күйді сақтайды, әрекетті күйге береді, `synchronized`.

Қосымша шешім: **STOPPED → ACTIVE** (қайта іске қосу) рұқсат етіледі — тапсырмада тыйым жоқ, ал онсыз тоқтатылған плагинді тек қайта орнату арқылы қосуға болар еді.

Менеджер алдымен `state().start()` шақырып ауысудың заңдылығын тексереді (бұл таза функция, күйді өзгертпейді), тек содан кейін плагин кодын шақырады, ал сәтті болса ғана `lifecycle.start()`. Сондықтан сәтсіз `start()` күйді өзгертпейді.

## Салдары

+ Жаңа күй (мысалы, UNINSTALLED) = бір жаңа enum тұрақтысы.
− Күйге деректер (мысалы, қате себебі) керек болса, enum-нан класқа өту қажет.
