# ADR-0004: API v1 / v2 — Adapter және нұсқа бойынша Abstract Factory

Мәртебесі: қабылданды
Күні: 2026-11-18 · Қатысушылар: Амангелді Мадияр

## Контекст

R4: плагин API-дің v1 (`init/process/destroy`) және v2 (`start(context)/handle/stop`) нұсқалары бар; v1 плагині **өзгертусіз** жұмыс істеуі керек. Хост ішінде барлық плагин бірдей (`Plugin`) болса, менеджердің коды қарапайым.

## Нұсқалар

1. **Менеджерде `if (api == 1) ... else ...`.**
   − Нұсқа тексерісі әр әрекетте (start/handle/stop) қайталанады; v3 қосу менеджерді өзгертеді.
2. **v2 интерфейсін v1-ден мұрагерлеу + default әдістер.**
   − Ескі плагин қайта компиляцияланбайды, сондықтан оның класы жаңа интерфейсті іске асырмайды — жұмыс істемейді.
3. **Adapter + әр нұсқаға бір Abstract Factory (таңдалды).**
   + `LegacyPluginAdapter` v1-ді v2-ге айналдырады; менеджер тек `Plugin`-мен жұмыс істейді.
   + `PluginRuntimeFactory` нұсқаға тән объектілер **отбасын** жасайды: плагин объектісі және `PluginContext` (v1 үшін логтар `[api-v1]` белгісімен).
   + Менеджер фабриканы `apiVersion` бойынша `Map`-тан алады; v3 = жаңа фабрика + `createDefault`-та тіркеу.

## Шешім

3-нұсқа. Плагин класының дұрыс интерфейсті іске асыратыны жасау кезінде тексеріледі (`does not implement ... (api=N)` қатесі).

## Салдары

+ v1 плагині (`LegacyUpperPlugin`) өзгертусіз жұмыс істейді — `PluginManagerTest`.
− v1 плагині контекст алмайды (API-да жоқ), сондықтан оның атынан адаптер логтайды.
