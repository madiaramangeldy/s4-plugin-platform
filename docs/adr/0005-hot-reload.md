# ADR-0005: Hot reload — алдымен жаңасы, сосын ескісі; жад ағуын WeakReference-пен дәлелдеу

Мәртебесі: қабылданды
Күні: 2026-11-18 · Қатысушылар: Амангелді Мадияр

## Контекст

R6: плагинді хостты қайта іске қоспай жаңарту; ескі нұсқа шығарылады, жад ағуы жоқ. «Қиын тұс»: ескі ClassLoader GC-мен жиналуы керек, тест мұны WeakReference арқылы дәлелдейді.

## Нұсқалар

1. **Алдымен ескісін тоқтату, сосын жаңасын іске қосу.**
   + Екі нұсқа бір мезгілде жұмыс істемейді.
   − Жаңасы іске қосылмаса, ескісін қайта қосу керек; аралықта плагин қолжетімсіз.
2. **Алдымен жаңасын жүктеп, іске қосу; сәтті болса ғана ескісін тоқтату (таңдалды).**
   + Қате болса — ескі нұсқа тиіспей жұмысын жалғастырады (`failedReloadKeepsOldVersionRunning`).
   + Үзіліс жоқ.
   − Қысқа уақыт екі нұсқа қатар белсенді; бөлісілетін сыртқы ресурсы бар плагиндер үшін бұл мәселе болуы мүмкін.

## Шешім

2-нұсқа. Жаңа JAR алдымен тексеріледі: id сәйкес пе, тәуелділік циклі жоқ па, тыйым салынған API жоқ па. Ескі нұсқаны босату (`LoadedPlugin.close`): плагин ағыны тоқтатылады (`shutdownNow` + `awaitTermination`), JAR жабылады (`URLClassLoader.close`), менеджердің картасынан сілтеме жойылады.

Ағуды болдырмау үшін:
- плагин ағыны `ThreadPoolExecutor`-мен тікелей жасалады (JDK-ның `Executors` орауышы Cleaner-ге тіркеледі және босатуды кешіктіреді);
- ағынның context class loader-і тек сол ағын тірі кезде ғана сілтеме ұстайды;
- хост плагин объектісіне тек `LoadedPlugin` арқылы сілтеме ұстайды.

## Салдары

+ `HotReloadMemoryTest`: бір reload-тан кейін және 10 рет қатарынан reload-тан кейін ескі loader-лердің бірде-бірі жадта қалмайды.
− Карантиндегі (циклге түскен) плагин үшін бұл кепіл жоқ — ADR-0003.
