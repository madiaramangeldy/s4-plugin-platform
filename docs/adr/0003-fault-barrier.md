# ADR-0003: Fault barrier — жеке ағын + timeout + карантин, System.exit — статикалық тексеру

Мәртебесі: қабылданды
Күні: 2026-11-18 · Қатысушылар: Амангелді Мадияр

## Контекст

R5: плагиндегі исключение, шексіз цикл немесе OutOfMemoryError хостты құлатпауы керек. Қабылдау шарты: зиянды плагин (шексіз цикл, `System.exit`) хостты тоқтата алмайды.

Шектеулер:
- Java-да ағынды күштеп өлтіру мүмкін емес (`Thread.stop` жойылған).
- SecurityManager Java 17-де deprecated for removal, Java 24-тен бастап мүлдем қосылмайды → `System.exit`-ті орындалу кезінде бөгеудің сенімді жолы жоқ.

## Нұсқалар

### Ұзақ/құлайтын шақырулар үшін

1. **Плагинді хост ағынында `try/catch`-пен шақыру.** − Шексіз цикл хостты мәңгі бөгейді.
2. **Әр плагинге жеке ағын + `Future.get(timeout)` (таңдалды).**
   + Хост ағыны тек timeout-қа дейін күтеді.
   + `FutureTask` кез келген `Throwable`-ды (OOM, StackOverflowError) ұстайды.
   − Цикл ағыны тоқтамайды → daemon ағын ретінде қалады; плагин **карантинге** түседі (кейінгі шақырулар бірден қабылданбайды) және STOPPED күйіне өтеді.
3. **Әр плагинді бөлек JVM процесінде іске қосу.**
   + Нағыз изоляция: процесті өлтіруге болады, `System.exit` тек сол процесті тоқтатады.
   − IPC, сериализация, бөлек іске қосу — 1,5 апта мерзімге тым күрделі. Келешекте ең дұрыс жол.

### System.exit үшін

1. **SecurityManager.** − Java 24+-та жұмыс істемейді, deprecated.
2. **Байт-кодты статикалық тексеру (таңдалды).** `ForbiddenApiScanner` JAR-дағы әр `.class` файлдың constant pool-ын оқып, `java/lang/System.exit`, `Runtime.exit`, `Runtime.halt` сілтемелерін іздейді. Табылса, плагин **ешбір коды орындалмай** қабылданбайды.
   + JDK нұсқасына тәуелсіз, сыртқы кітапхана жоқ (ASM қолданбадық — оны өзіміз оқимыз).
   − Рефлексия арқылы шақыру (`Method.invoke`) көрінбейді.

## Шешім

Ағын + timeout + карантин (`FaultBarrier`, Proxy ретінде `FaultBarrierPlugin`) және статикалық сканер (`ForbiddenApiScanner`). Плагин объектісінің өзі де (конструктор, static блоктар) barrier ішінде жасалады, сондықтан плагин коды ешқашан хост ағынында жүрмейді.

## Салдары

+ `MaliciousPluginTest`: boom / oom / deep / loop шабуылдарынан кейін хост жауап береді; `PluginManagerTest.pluginCallingSystemExitIsRejectedBeforeAnyCodeRuns`.
− Белгілі шектеулер (README-де): (1) циклге түскен ағын JVM жабылғанша CPU-ды жейді және сол плагиннің кластары жадта қалады; (2) рефлексия арқылы `System.exit` ұсталмайды; (3) нағыз жад шектеуі жоқ — бір JVM ішінде плагиннің жадын шектеу мүмкін емес. Үшеуін де толық шешетін — 3-нұсқа (бөлек процесс).
